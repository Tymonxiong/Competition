---

每局比赛将双方选手代码同时启动，选手代码通过httpserver方式启动运行并监听端口，判题系统通过http请求方式向选手程序发送当前地图状态数据并获取选手调度命令响应数据。

样例：bash run.sh port

说明：port为系统启动时传给选手程序的端口号，ip地址均为0.0.0.0

# 1 Request

## 1.1 顶层结构

| 字段 | 数据类型 | 字段说明 |
|------|---------|---------|
| `roundNo` | int | 当前回合数 |
| `mapInfo` | MapInfo | 地图整体信息 |
| `teamOur` | TeamOur | 我方队伍全部信息 |
| `teamEnemy` | TeamEnemy | 敌方队伍可见信息 |
| `robot` | Robot | 当前场上机器人信息（包括系统生成与召唤生成机器人） |
| `phaseTask` | String | 当前已领取任务的原文描述 |
| `lastRoundRoleActionResults` | Map\<int, boolean\> | 上回合各角色动作执行合法性结果，key是角色ID或可控机器人ID，value=true合法，反之不合法 |
| `lastSummonTreasureResult` | int | 上回合 `summonTreasure` 结果码：`0`=未探测。指的是上一回合没使用`summonTreasure`动作，或者该动作非法；`1`=成功获取宝藏；`2`=无宝藏或宝藏暂未开启。指的是`targetPos`无宝藏或者没到宝藏开启时间；`3`=献祭物品错误。指的是传递的`item`中的物品错误，要求不能多、不能少，无顺序限制，否则都会报该结果码；4=宝藏已空 |
| `llmResp` | String | 上回合LLM 返回的响应内容 |
| `worldNews` | WorldNews | 包括官方消息与民间传闻 |
| `lastCmdResult` | String | 上回合 `executeCmd` 的执行结果，未发命令时为空字符串 `""`。格式约定：第一行为状态头——正常 `"[exitCode:N]"`（N 为退出码）、超时 `"[TIMEOUT]"`、判题器侧异常 `"[JUDGER_ERROR]"`；第二行固定为 `"[durationMs:N]"`，命令的真实运行耗时，单位毫秒；随后是输出内容，超时为部分输出，异常为原因文本；输出超过 64KB 时末尾追加一行 `"[TRUNCATED]"`。完整形态：`"[exitCode:N]\n[durationMs:N]\n<输出>"` |
| `vendorShopList`             | Array                         | 小贩收购矿石清单与价格                                       |
| `weaponShopList`             | Array                         | 武器商店出售物品清单与价格，元素为 `{name: String, price: int}`，分别对应商品名称与价格 |
| `errors` | Error[] | 本轮产生的错误信息数组 |

| `vendor` | 小贩 |

| `challengerTaskPoint2` | 挑战者任务点2 |
| `defenderTaskPoint1` | 防守者任务点1 |
| `defenderTaskPoint2` | 防守者任务点2 |
| `challengerVehicle` | 挑战者可驾驶小车 |

## 1.3 TeamOur — 我方队伍信息

| 字段 | 数据类型 | 字段说明 |
|------|---------|---------|
| `type` | String | 阵营标识，取值 `challenger`（挑战者）/ `defender`（防守者） |

### 1.3.1 Role — 单位通用属性

| 字段 | 数据类型 | 字段说明 |
|------|---------|---------|
| `id` | int | 角色 / 单位唯一编号 |
| `pos` | Pos | 单位所在坐标 |
| `roleType` | String | 单位分类，取值见下表 |
| `health` | int | 当前剩余血量 |
| `attackPower` | int | 攻击力数值 |
| `attackRange` | int | 攻击距离 |
| `backPackCapability` | int | 背包容量上限 |
| `backpack` | String[] | 背包内物品名称列表 |
| `level` | int | 等级。仅建筑持有，角色没有，初始等级1 |
| `cooldown` | int | 武器冷却剩余回合数，当前仅火箭发射台有冷却，加特林/电磁炮恒为0 |
| `isDriving` | bool | 驾驶标志，表示当前角色是否处于驾驶状态 |

**roleType 取值：**

| 值 | 说明 |
|----|------|

### 1.3.2 PlayerTask — 任务点信息

| 字段 | 数据类型 | 字段说明 |

## 1.7 Errors — 错误结构体

| 字段 | 数据类型 | 字段说明 |
|------|---------|---------|
| `errorCode` | int | 错误编码 |
| `description` | String | 错误文字描述 |

注：errorCode包含如下字段：

0-未知错误

1-任务超时

2-答案错误

3-网络错误

4-指令错误

5-LLM额度超限

注：

- 2-答案错误，即通过`submitAnswer`提交的答案不正确或者不完全正确。
- 5-LLM额度超限，每队每个游戏日（130回合） LLM 调用次数存在限制，在每个游戏日的第一个回合重置。当前每个游戏日只能调用3次 LLM，超出则会此错误。但是在自进化任务执行期间(接取任务到任务结束期间)不会受到此限制，并且在此期间调用LLM不会计入每个游戏日的LLM限制次数。

# 2 Response

## 2.1 顶层结构

| 字段 | 数据类型 | 说明 |
|------|---------|------|
| `roleCommandMap` | Map\<int, RoleCommand\> | 全角色指令集合。key = 角色 ID，value = 对应角色动作指令；其中key也包括可控机器人 ID |
| `prompt` | String | 提交给 LLM 的 prompt 内容，每个游戏日有调用次数限制，超出则会报错。详见上文对errorCode字段解释 |
| `executeCmd` | String | 沙盒环境中执行的命令，仅在执行任务期间才能使用 |

`executeCmd` 为选手提交到沙盒环境的命令。判题器会在本回合执行，执行时长不得超过15秒，否则视为执行指令超时，沙盒故障与命令超时均不计入队伍异常次数。

## 2.2 RoleCommand — 单角色指令

| 字段 | 数据类型 | 是否必选 | 说明 |
|------|---------|:---:|------|
| `action` | String | M | 执行动作标识，取值见下表 |
| `controllerId` | String | O | 操控武器攻击的角色ID，一个角色只能同时操控一座武器工事 |
| `targetPos` | Array\<Pos\> | O | 目标坐标数组。移动/建造/拆除/采集/使用/召唤宝藏/电磁狙击炮均只传1个目标位置；加特林/火箭发射台可传多个目标位置，目标位置数与当前武器等级数相同 |
| `name` | String | O | 操作对象名称 |
| `num` | Int | O | 购买 / 贩卖物品需要使用，表示购买n个物品，贩卖n个矿石，若不填则默认为1 |
| `taskAnswer` | String | O | 任务作答内容 |
| `item` | Array\<String\> | O | `summonTreasure` 献祭任务用品名称数组 |

## 2.3 动作码全集

| 动作码 | 说明 |
|--------|------|
| `move` | 移动角色、可控机器人、驾驶小车时需指定目标坐标`targetPos`； |
| `attack` | 操控武器攻击指定坐标，需指定目标坐标数组`targetPos` ，`controllerId`为控制武器的角色ID；仅夜晚可用，白天使用非法；可控机器人亦可用 `attack` 指令攻击对方英雄/基地/建筑 |
| `sell`        | 卖出矿石换取金币，需指定物品名称`name`以及物品数量`num`，`num`不填则默认为1    |
| `buy` | 在武器商店购买商品，需指定物品名称`name`以及物品数量`num`，`num`不填则默认为1 |
| `build` | 建造围墙或武器工事，需指定建造建筑名称`name`与建造的目标坐标`targetPos` |
| `remove` | 拆除围墙，需指定想要拆除的围墙坐标`targetPos` |
| `acceptTask` | 领取任务，无额外参数 |
| `submitAnswer` | 提交任务答案，需指定提交的答案`taskAnswer` |
| `summonTreasure` | 献祭任务用品，召唤并开启祭坛宝藏；需指定 `targetPos`与献祭任务用品 `item`，`item`中的任务用品需要在背包中存在 |
| `use` | 使用背包中的消耗品 / 升级券，需指定待使用物品名称`name`；使用机器人召唤令必须携带召唤位置 `targetPos`。 |
| `drop` | 丢弃背包内指定物品，需指定物品名称`name` |
| `collect` | 采集矿石，需指定矿石坐标`targetPos` |
| `destroy` | 破坏矿物，需指定目标矿坐标 targetPos，需连续 4 个回合每回合执行（任一回合未执行——包括原地待命、执行其他动作、指令非法——即打断清零，重新累计） |
| `catch` | 抓捕 8 邻域内的敌方捣乱鬼，需指定目标坐标 targetPos；成功 +20 金币，目标当场阵亡 |

注：

- 对`summonTreasure`动作的额外补充说明：
  - 动作非法场景：`targetPos`不在开拓者周围一格，或者说`item`中的物品不存在于背包内，动作非法不会消耗任务用品。
  - 只要动作合法，不论是否开启祭坛，都会消耗掉任务用品。
- 响应报文例子详见`response.txt`。每个角色每回合至多提交 1 条指令， **`response.txt` 内同一角色 ID 重复出现，仅为列举全部动作变体的目录式写法，并非意味着同一回合一角色能够执行多条指令**。
